# (주)대경하이켐 웹사이트 리뉴얼 — 설계 플랜

## Context
현행 dkhc.co.kr은 2018년 Classic ASP 사이트. 제품이 "카테고리→메이커 로고"로만 탐색되어 찾기 어렵고, 연혁·카테고리가 방치됐고, HTTPS·SEO가 없음(분석: `docs/analysis/2026-10-15-current-site.md`).
회사 요구는 딱 두 가지 — **① 취급 제품을 보기 쉽게 ② 깔끔한 느낌**. 운영 조건 — **직원이 혼자 굴릴 수 있어야 함**(구글 시트 수준의 CMS OK), **문의 메일이 확실히 가야 함**, **한/영/일 3개 언어 필수**(번역은 회사가 검수). 납품 후 재영이 가끔 손봐줄 수 있음.
레퍼런스 IMCD Korea는 Salesforce Experience Cloud — 우리는 그 *디자인 토큰 감각*만 가져오고 스택은 가볍게 간다.

## 1. 스택 (2026 기준, 가볍고 트렌디한 쪽)

| 역할 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Astro 5** | 정적 HTML 출력(빠름·SEO), i18n 라우팅 내장(`/ko /en /jp`), 빌드 때 외부 데이터(시트) 읽기 쉬움. React 없이 섬(island)만 필요한 곳에 |
| 스타일 | **Tailwind CSS v4** | CSS 변수 기반 디자인 토큰(`@theme`)으로 IMCD식 일관성. 컴포넌트는 직접 작성(shadcn 패턴 참고, 라이브러리 의존 X) |
| 폰트 | **Pretendard Variable**(한/영) + **Noto Sans JP**(일) | 한글 사이트의 사실상 표준, 가변 폰트 1파일. IMCD의 Noto Sans 톤과 동일 계열 |
| 인터랙션 | Astro View Transitions + CSS 트랜지션, 필터는 바닐라 JS 섬 | 페이지 전환 부드럽게, JS 최소 |
| 데이터(CMS) | **Google Sheets** (회사 전용 구글 계정 소유) | 직원이 셀 고치면 끝 |
| 빌드/배포 | **GitHub Actions → GitHub Pages**, 커스텀 도메인 `dkhc.co.kr` + HTTPS | NEWSCAPE/64 Moves와 같은 경로. 비용 0 |
| 문의 메일 | **Google Apps Script** 웹앱 → `MailApp` → `info@dkhc.co.kr` + 시트 `inquiries` 탭에 기록 | 회사 계정에서 발송되니 수신 확실, 로그 남음, 비용 0 |
| 스팸 방지 | 허니팟 + 제출 시간 체크 + Cloudflare Turnstile(무료) | 캡차 이미지 대체, 깔끔 |

폐기한 대안: 실시간 시트 읽기(SEO·안정성 불리), 워드프레스/아임웹(관리 부담), Salesforce(비용).

**계정 소유권(중요):** 시트·Apps Script·Turnstile은 **회사 전용 구글 계정**(Workspace면 `info@`, 아니면 `dkhc.web@gmail.com` 신규)으로. 직원 개인 계정 금지 — 퇴사하면 폼이 죽는다. GitHub 리포는 재영(`gamsasyo/dkhc`, private)이 보유.

## 3. 시트 구조

시트 1개, 탭 4개. 언어는 `_ko/_en/_jp` 접미 칼럼으로 나란히 → 직원이 검수하며 채우기 쉬움.

```
products   id | category | tags | maker_id | name_ko | name_en | name_jp
           | summary_ko/en/jp | body_ko/en/jp(마크다운 허용) | features_ko/en/jp(줄바꿈 구분)
           | image(선택, Drive 공유링크 or 빈칸) | datasheet_url(선택) | order | published(TRUE/FALSE)

makers     id | name | country | logo(파일명, 리포 /src/assets/makers/에 보관) | url
           | desc_ko/en/jp | order | published

history    year | text_ko | text_en | text_jp

inquiries  (Apps Script가 자동 기록 — 직원은 읽기만) timestamp | type | name | email | company | ... | status
```
- `category`는 고정 3값: `special` / `medical` / `eco`. 라벨 번역은 코드에.
- `tags`는 쉼표 구분 자유 태그(Resin, Film, Syringe…). 기존 서브카테고리 11개를 초기값으로 시딩.
- 메이커 로고(~25개)는 리포에 보관 — 거의 안 바뀌고, 로고는 화질·배경 정리가 필요해서 재영이 관리하는 게 결과물이 깔끔함. 새 메이커 추가 시에만 재영에게 요청.
- 빌드 스크립트가 필수값 누락·잘못된 `maker_id`를 **빌드 실패 + 어떤 행인지 메시지**로 알려줌(직원이 시트 보고 고칠 수 있게 한국어로).
- 회사 소개 본문(개요·인사말)은 리포 마크다운(`src/content/company/*.{ko,en,jp}.md`) — 수년에 한 번 바뀜.

```
│                          → 대표 제품 카드 6 → 고객사 로고 띠 → 문의 CTA

│                          카드 = [분야 태그] 제품명 · 요약 2줄 · 메이커 로고 · [견적 문의]
├─ /products/{id}         제품 상세: 본문 · 특징 · 메이커 박스 · 같은 메이커 제품 · [견적 문의](제품명 프리필)

├─ /contact               문의: 고객문의/협력문의 탭 하나의 폼, 제품 상세에서 오면 제품명 자동 입력
└─ /privacy
```
### 4-1. 제품 페이지 — "찾기 쉽게"의 구체안 (최우선)

방문자는 4가지 중 하나를 들고 온다: **소재 종류**(Resin/Film), **용도**(의료 실린지, 방열), **메이커 이름**(Kuraray), **브랜드명**(GENESTAR, APEL). 넷 다 한 화면에서 막힘없이 통해야 한다.

```
┌─ /products ──────────────────────────────────────────────────────────────┐
│ 헤더  [로고] [분야 선택 ▾ | 🔍 제품·메이커·소재 검색      ]  (문의)   │ ← IMCD 헤더 콤보, 전 페이지 상시
├───────────────────────────────────────────────────────────────────────────┤
│  (분야 틴트 그라데이션 띠)   SPECIAL MATERIAL  ← 눈썹 라벨                 │
│                              제품                                        │
├───────────────────────────────────────────────────────────────────────────┤
│  분야를 선택하세요                                                        │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐                       │
│  │ ✓ Special    │ │   Medical    │ │ Eco-Friendly │  ← IMCD "Business     │
│  │   Material   │ │              │ │              │    Group" 이미지 타일  │
│  └──────────────┘ └──────────────┘ └──────────────┘    (추상 그래픽 배경)  │
│                                                                           │
│  Special Material 의 세부 분야                                            │
│  (● 전체) (Resin 8) (Film 9) (Metal 4) (Machine 2) (Thermal 1)  ← pill 행 │
│                                                                           │
│  'Special Material' 결과 18개                              정렬 [추천 ▾]  │
│  ┌───────────────────────────────────────────────────────────────────────┐│
│  │ Special Material · Resin                     자세히 보기 ›  ┌───────┐ ││
│  │ GENESTAR (PA9T)                                            │Kuraray│ ││
│  │ 내열성·저흡수 폴리아미드. 커넥터·LED 리플렉터… (2줄 말줄임) │ 로고   │ ││
│  │                                                            Principal ││
│  │ [⬇ 자료 요청] [견적 문의]                                              ││
│  └───────────────────────────────────────────────────────────────────────┘│
│  ┌─ 다음 카드 (풀폭 가로 카드, IMCD와 동일한 리스트형) ─────────────────┐│
└───────────────────────────────────────────────────────────────────────────┘
```
재영 요구: **IMCD의 제품 검색·탐색 UX를 그대로 닮게.** 위 레이아웃은 IMCD `/our-products` 구조(분야 타일 → 세그먼트 pill → 리스트형 카드)를 3분야 규모로 축소한 것.

- **헤더 검색 콤보**: `[분야 선택 ▾ | 검색창]` 이 IMCD처럼 모든 페이지 헤더에 상시. 입력 즉시 드롭다운 제안(제품 · 메이커 · 태그 섹션 구분), Enter → `/products?q=`.
- **분야 타일 3개**: 이미지 대신 분야별 틴트의 추상 그래픽. 선택 시 체크 배지 + 테두리 강조(IMCD와 동일). 타일 아래 세부 분야 pill 행이 선택된 분야에 맞춰 교체.
- **세부 분야 pill**: `(전체)` 기본 선택, 각 pill에 개수. 0개는 흐리게. 다중 선택 아님(IMCD도 단일) — 단순하게.
- **검색**: 제품명·브랜드·메이커·태그·요약, 3언어 전부 대상(일본 메이커를 영문/가타카나로 쳐도 잡히게). 제품 수십 개 → 전부 클라이언트, 로딩 없음.
- **결과 카드 = IMCD 리스트형 가로 카드**: 눈썹(분야 · 세부) → 제품명 → 요약 2줄 → 우측 메이커 로고 + "Principal" 라벨 → 하단 버튼 [자료 요청] [견적 문의]. 카드 전체 클릭 = 상세. 2열 그리드가 아니라 **1열 풀폭 리스트**(IMCD 동일, 스캔하기 쉬움).
- **URL 상태**: `?cat=special&seg=resin&q=pa9t` → 공유·뒤로가기 정상.
- **페이지네이션 없음**(IMCD는 676개라 있지만 우리는 수십 개).
- **빈 결과**: "조건에 맞는 제품이 없어요" + 같은 분야 전체 보기 + 문의 유도.
- **상세 페이지**: 좌 본문(설명·특징·용도) / 우 고정 박스(메이커 로고 · 분야 · 세부 · [견적 문의] [자료 요청]). 하단 = 같은 메이커 제품 / 같은 세부 분야 제품.
- **공급사 `/makers` = IMCD `/our-suppliers` 닮게**: 상단 동일한 분야 타일 3개 → **A–Z 인덱스 바** → 메이커 카드 그리드(로고 + 이름 + "제품 N개" + ›). 메이커 상세 = 소개 + 그 메이커 제품 리스트형 카드.
- 모바일: 분야 타일은 가로 스크롤, pill 행도 가로 스크롤, 헤더 검색은 아이콘 → 전체화면 검색.

- 헤더: 로고 · 제품 · 공급사 · 회사소개 · 문의 · 언어(KO/EN/JP) · 모바일 햄버거. 문의는 알약 버튼(IMCD의 "Get access" 자리).
- 기존 URL(`/ko/sub/product/list.asp?...`)은 → 새 경로로 리다이렉트 맵(`_redirects` 대신 Astro `redirects` 설정) — 검색 유입 보존.
- 외부 dk3d 링크 제거. 빈 카테고리(Special Packaging, Biodegradable)는 시트에 제품이 생기면 자동 노출.

## 6. 작업 단계 (각 단계 끝에 재영 확인)

1. **리포 셋업** — `~/REN/github/dkhc` git init, Astro 5 + Tailwind 4 + i18n 스캐폴드, GitHub Pages 워크플로. 토큰·공통 컴포넌트(Button/Card/Pill/Input/Section) 먼저 → 스타일 가이드 페이지 `/styleguide`로 눈 확인.
2. **시트 + 데이터 레이어** — 시트 템플릿 생성(현행 콘텐츠 시딩: 제품 ~25건·메이커 ~25·연혁 10줄·3언어), `scripts/fetch-sheet.ts`(CSV → `src/data/*.json`, 검증 메시지 한국어), Astro content에서 소비.
3. **페이지** — 제품 목록/상세 → 공급사 → 홈 → 회사 → 문의. 3언어 라우팅. 모바일 우선 확인.
4. **문의 메일** — Apps Script 웹앱(메일 + inquiries 기록 + Turnstile 서버 검증), 폼 성공/실패 UI, 실제 수신 테스트.
5. **배포/인수인계** — `dkhc.co.kr` DNS → GitHub Pages(HTTPS), 구 URL 리다이렉트, 시트 [사이트 반영] 버튼, **직원용 한 장짜리 운영 가이드**(시트 편집 → 버튼 → 1~2분 뒤 반영 / 문의는 메일+시트 / 문제 시 재영 연락).

## 검증
- `npm run build` 3언어 전 페이지 생성, Lighthouse 모바일 90+ (성능/접근성/SEO)
- 시트에서 제품 1건 수정 → [사이트 반영] → 2분 내 라이브 반영 확인
- 문의 폼 제출 → `info@dkhc.co.kr` 수신 + `inquiries` 탭 기록 + 스팸(허니팟 채움) 차단 확인
- 구 URL 5개 샘플 → 새 경로 301 확인
- 직원 1명이 가이드만 보고 제품 추가 성공하면 인수 완료

## 확정된 전제 (2026-10-15)
- **구글 계정**: 회사 전용 계정 곧 전달 예정 → 올 때까지 시트는 재영 계정으로 만들고, 오면 소유권 이전(시트 "소유자 변경" + Apps Script 재배포).
- **DNS/호스팅**: **가비아**. 재영이 계정 받음. 작업 = 가비아 DNS에서 `A`(apex, GitHub Pages IP 4개) + `CNAME www` 설정. **MX/TXT(메일) 레코드는 절대 건드리지 않음** — `info@dkhc.co.kr`이 가비아 메일일 가능성 높음. 변경 전 현재 레코드 전체 스크린샷/백업.
- **메이커 로고**: 현행 사이트 `/upload/prod/*` 수거 → 배경 제거·크기 통일(높이 40px 기준 PNG@2x)해서 리포에. 요청한 원본 오면 교체.
